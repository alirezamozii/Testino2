# راهنمای جامع کاربر و مدیر تستیونو (Testino User & Admin Guide)

این راهنما مستندات رسمی کاربری و فنی سامانهٔ آزمون‌گیر محلی و ابری **تستیونو (Testino)** است.

---

## ۱. ورود سؤالات (Import System)

### ۱.۱. فرمت‌های پشتیبانی‌شده
سامانه از دو قالب فایل برای ورود سؤالات پشتیبانی می‌کند:
1. **فایل JSON استاندارد**: حاوی مشخصات سؤالات، گزینه‌ها، کلید پاسخ و فیلدهای taxonomy.
2. **بستهٔ ZIP رسانه‌دار (`.zip`)**: شامل فایل `questions.json` و پوشهٔ `media/` شامل تصاویر ارجاع‌شده.

### ۱.۲. ساختار سؤال در فایل JSON
```json
{
  "schemaVersion": "1.0",
  "defaults": {
    "subject": "زبان انگلیسی عمومی",
    "chapter": "گرامر",
    "status": "published"
  },
  "questions": [
    {
      "externalKey": "eng-1402-q01",
      "subject": "زبان انگلیسی عمومی",
      "topic": "زمان‌های گذشته",
      "content": [
        { "type": "text", "value": "Which sentence is grammatically correct?" }
      ],
      "options": [
        { "key": "a", "content": [{ "type": "text", "value": "He went to school yesterday." }] },
        { "key": "b", "content": [{ "type": "text", "value": "He go to school yesterday." }] },
        { "key": "c", "content": [{ "type": "text", "value": "He has went to school." }] },
        { "key": "d", "content": [{ "type": "text", "value": "He is go to school." }] }
      ],
      "correctKey": "a",
      "shuffleSafe": true,
      "explanation": [
        { "type": "text", "value": "گزینه الف صحیح است زیرا فعل گذشته ساده went استفاده شده است." }
      ]
    }
  ]
}
```

### ۱.۳. قواعد اعتبارسنجی
- حداکثر حجم فایل ورودی: ۲۰ مگابایت یا ۱۰,۰۰۰ سؤال در هر نوبت.
- گزینه‌ها در حالت انتشار (`published`) باید دقیقاً ۴ گزینه باشند.
- گزینه‌های دارای کلیدهای وابسته به مکان (مثل «گزینه ۱ و ۲ صحیح است») باید پرچم `shuffleSafe: false` داشته باشند تا چیدمان تصادفی آن‌ها را جابه‌جا نکند.
- تصاویر ارجاع‌شده باید از فرمت‌های معتبر `image/png`، `image/jpeg` یا `image/webp` و حداکثر ۵ مگابایت با ابعاد زیر ۴۰۹۶×۴۰۹۶ باشند.

## ۲. مدیریت پرامپت‌ها و لایهٔ هوش مصنوعی (AI Prompt Manager)

تستیونو شامل یک موتور مدیریت پرامپت داخلی بدون نیاز به اینترنت است:
- **تب‌های سه‌گانه**:
  - `extract`: استخراج سؤالات چهارگزینه‌ای از متن آزمون‌ها یا جزوات.
  - `generate`: تولید سؤالات جدید بر اساس سرفصل و مباحث درسی مشخص.
  - `analyze`: تحلیل عملکرد، شناسایی نقاط ضعف و ارائهٔ راهکارهای مطالعاتی.
- **تزریق Placeholderها**: فیلدهای `{subject}`, `{topic}`, `{grade}`, `{question_count}` به صورت امن جایگزین می‌شوند.
- **Export برای هوش مصنوعی**: کاربر می‌تواند عملکرد آزمون خود را به صورت JSON استاندارد ناشناس‌سازی‌شده (بدون اطلاعات هویتی) جهت ارسال به چت‌بات‌های خارجی دریافت کند.

## ۳. پشتیبان‌گیری و بازیابی (Backup & Restore)

### ۳.۱. پشتیبان‌گیری
- فایل خروجی با پسوند `.testino` یک فایل فشردهٔ ZIP رمزنگاری‌نشده و استاندارد است.
- شامل:
  - `manifest.json`: متادیتای پایگاه داده، تعداد جداول، تاریخ خروجی و هش داده‌ها.
  - `data.json`: اطلاعات کامل پروفایل‌ها، درس‌ها، سؤالات، آزمون‌ها و تلاش‌ها با حذف توکن‌ها و شناسه‌های ابری.
  - پوشهٔ `media/`: تمام تصاویر ذخیره‌شده بر اساس هش SHA-256.

### ۳.۲. بازیابی امن (Atomic Restore)
- قبل از اعمال هرگونه تغییر به دیتابیس فعلی، مانیفست و چکسام فایل به‌دقت بررسی می‌شود.
- در صورت مخدوش بودن فایل حتی ۱ بایت از اطلاعات فعلی دستگاه دستکاری نخواهد شد.
- بازیابی تمام جداول در قالب یک تراکنش واحد انجام می‌شود.

---

## ۴. کارکرد آفلاین و PWA (Offline Shell)

- **دیتابیس محلی دستگاه**: از SQLite3 کامپایل‌شده به WASM و پایگاه دادهٔ OPFS / IndexedDB با پایداری داده‌ها بهره می‌برد.
- **Service Worker**: تمامی استایل‌ها، فونت‌های محلی، فایل‌های WASM و کدهای برنامه را کش می‌کند تا در صورت قطع کامل اینترنت یا حالت پرواز (Airplane Mode)، آزمون‌ها بدون وقفه اجرا شوند.
- **مدیریت تایمر فعال**: تایمر آزمون هنگام کوچک شدن پنجره یا جابه‌جایی تب متوقف می‌شود تا زمان خالص حل سؤال محاسبه شود و زمان‌های خواب رفتن دستگاه باعث اختلال در آمار نشود.

---

## ۵. حساب کاربری ابری و همگام‌سازی (Cloud Sync)

- **ورود با گوگل (PKCE)**: ارتباط امن و بدون ذخیرهٔ اطلاعات حساس در کلاینت.
- **انتقال مالک محلی (Claim Local Owner)**: با اتصال حساب گوگل، سؤالات و آزمون‌های قبلی کاربر به حساب متصل شده و پشتیبان خودکار ایجاد می‌گردد.
- **همگام‌سازی محدود و امن (Bounded Push/Pull)**: تبادل تغییرات در قالب بسته‌های ۵۰ تا ۱۰۰ تایی با پیشگیری از خطای تکراری با مکانیزم Mutation Receipts.
- **Recovery Fork**: در صورت ویرایش همزمان یک آزمون در دو دستگاه مختلف، برنامه نسخهٔ محلی را در شاخهٔ بازیابی (`recovery fork`) نگهداری می‌کند تا هیچ پاسخی از بین نرود.

---

## ۶. محدودیت‌های معماری و حریم خصوصی
- هیچ ضریب یا دادهٔ ساختگی بدون ورود کاربر تزریق نمی‌شود.
- آمار شخصی و کارنامهٔ آزمون‌ها هرگز با دیگر اعضای یک بانک مشترک به اشتراک گذاشته نمی‌شود.
- ذخیرهٔ محلی همواره قبل از ارسال تأییدیه به کاربر کامل می‌شود.

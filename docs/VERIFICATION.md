نسخهٔ اولیهٔ این فایل برای ثبت شواهد آینده است. نبود نتیجه به معنی موفقیت نیست.

## بررسی مستندات این تحویل
- کنترل وجود فایل‌ها و لینک‌های Markdown محلی.
- بررسی parse نمونه‌های JSON کامل.
- کنترل شناسه‌های تسک و وابستگی به تسک موجود.
- مرور سازگاری رفتار session/score/review و مرز مستندات/پیاده‌سازی.
این کنترل‌ها بررسی اپ، امنیت عملی، performance یا build نیستند.

## سنجش عملکرد آینده
Dataset:10,000 سؤال متنی + مجموعهٔ مشخص تصاویر، با نسخه و اندازهٔ ثبت‌شده.
ثبت کن: زمان parse/validation/commit، مدت query صفحه50تایی، تأخیر پاسخ durable، peak memory، مدت build و حجم asset.
هدف اولیه روی دستگاه هدف: query صفحه بانک زیر300ms و پاسخ durable زیر200ms در p95؛ این‌ها **بودجهٔ طراحی** هستند، نه نتیجهٔ حاصل.
اگر اندازه‌گیری از بودجه عبور کرد، قبل از افزودن cache پیچیده SQL index و payload و worker را profile کن.

## رفع باگ اسپم دانلود PDF (IDM) و اجرای ممیزی جامع تعاملی ۱۰۰٪ (TASK-007 / UI-20) — 2026-09-10
- **بررسی ریشه‌ای و رفع باگ دانلود منیجر (IDM Spamming)**:

## همگام‌سازی چنددستگاهی و کتابخانهٔ انتخابی آفلاین — 2026-09-12
- **پوشش دادهٔ محلی:** پیش از هر push، وضعیت پایدار پروفایل/درس/فصل/موضوع، سؤال/گزینه/revision/media و جلسه/session-question/attempt/event/review به aggregateهای canonical تبدیل می‌شود. hash هر aggregate در `sync_entity_cache` نگه‌داری و mutation با شناسهٔ وابسته به content hash در outbox ثبت می‌شود؛ بنابراین مسیرهای قدیمی نوشتن نیز در sync جا نمی‌مانند و retry همان mutation را تکرار نمی‌کند.
- **چرخهٔ خودکار:** sync هنگام startup، برگشت online، foreground و هر ۳۰ ثانیه در foreground اجرا می‌شود. push و pull صفحه‌بندی‌شده تا پایان backlog ادامه دارند و cursor فقط همراه apply محلی در یک transaction جلو می‌رود.
- **تعارض:** attempt/event به شکل immutable حفظ می‌شوند؛ session نهایی‌شده با draft دوردست به عقب برنمی‌گردد؛ پاسخ متفاوت دو دستگاه آفلاین باعث fork شدن نسخهٔ محلی به جلسهٔ `PAUSED` و ثبت `sync_conflicts` می‌شود. revisionهای سؤال در migration ابری با هم union می‌شوند و head آخرین نسخهٔ پذیرفته‌شده است.
- **رسانه:** فایل‌های local با مسیر خصوصی کاربر در bucket غیرعمومی `question-media` upload می‌شوند. دریافت blob با SHA-256 manifest کنترل می‌شود و تنها بعد از ذخیرهٔ موفق وضعیت `both` می‌گیرد. renderer برای `mediaId` فاقد blob، هنگام مشاهده و وجود شبکه دریافت را بی‌صدا انجام می‌دهد و همان blob برای دفعات بعد آفلاین باقی می‌ماند.

# سیستم UI/UX تستیونو

این سند مرجع اجرای ظاهر برنامه است. تصاویر تحویلی کاربر زبان بصری را مشخص می‌کنند؛ قابلیت‌های محصول همچنان از `TESTINO_PRODUCT_BLUEPRINT.md` می‌آیند. وجود یک صفحه در تصویر به معنی اضافه‌شدن آن قابلیت به نسخهٔ یک نیست.

## 1. شخصیت بصری

- پس‌زمینه گرم و روشن، متن سرمه‌ای، آبی برای اقدام اصلی، نارنجی برای تأکید، سبز برای موفقیت، زرد برای هشدار و بنفش برای بانک/یادگیری.
- کارت سفید با خط ظریف و سایه کم؛ شعاع 18 تا 24 پیکسل و فاصله‌های منظم 8/12/16/24/32.
- تصویر و شخصیت فقط در شروع، onboarding و حالت خالی مهم استفاده می‌شود. صفحهٔ حل، فرم‌ها و فهرست‌ها باید آرام و کم‌حواس‌پرتی بمانند.
- رنگ تنها حامل وضعیت نیست؛ هر وضعیت متن یا آیکون نیز دارد.
- هیچ عدد نمایشی ساختگی نیست. هدف، پیشرفت، درصد و تعداد هر کدام با برچسب دقیق خود نمایش داده می‌شوند.

## 2. ساختار پاسخ‌گو

- موبایل زیر 768 پیکسل: نوار پایین پنج‌تایی خانه، بانک، آزمون، مرور و تحلیل. تنظیمات در سربرگ است.
- لپ‌تاپ از 1024 پیکسل: سایدبار راست 240 پیکسل، محتوای حداکثر 1200 پیکسل و کارت‌های چندستونه.
- صفحهٔ حل پوستهٔ عمومی ندارد. متن سؤال حداکثر 800 پیکسل است، کنترل‌های حرکت حداقل 44 پیکسل و پایین صفحه با safe-area سازگارند.
- هیچ صفحه‌ای نباید اسکرول افقی کلی ایجاد کند؛ جدول و فرمول بلند فقط داخل ظرف خود اسکرول می‌شوند.

## 3. کامپوننت‌های مشترک

| کامپوننت | کاربرد | قاعده |
|---|---|---|
| `PageIntro` | عنوان و اقدام اصلی صفحه | یک عنوان و حداکثر یک اقدام برجسته |
| `IconTile` | نشانهٔ رنگی بخش | رنگ بر اساس معنا، نه تزئین تصادفی |
| `MetricCard` | عدد واقعی با مخرج/توضیح | هدف با عملکرد مخلوط نشود |
| `ProgressRing` | درصد دارای مخرج روشن | بدون داده با خط تیره نمایش داده شود |
| `EmptyState` | نبود داده یا نتیجه | یک توضیح کوتاه و یک اقدام بعدی |
| `LoadingState` | انتظار واقعی | یک بار در سطح مناسب، بدون چند spinner تکراری |
| `ErrorState` | خطای قابل بازیابی | پیام کوتاه و retry در صورت امکان |

## 4. نگاشت تصاویر به صفحه‌های واقعی

| صفحهٔ واقعی | مرجع تصویری | تصمیم اجرا |
|---|---|---|
| شروع و onboarding | Splash / Setup Profile | جریان کوتاه و مرحله‌ای؛ بدون تأخیر نمایشی اجباری |
| خانه | Design System / Home | هدف‌ها، دسترسی سریع، جلسهٔ نیمه‌تمام و دادهٔ واقعی |
| بانک و ورود | Question Bank | جست‌وجو، فیلتر، افزودن دستی و JSON در مسیرهای موجود |
| ساخت آزمون | Create Test | فرم یکپارچه و پویا؛ مرحلهٔ نمایشی اضافه ساخته نمی‌شود |
| حل و ناوبری | Test Screen / Question Navigation | محیط متمرکز، progress، confidence و حرکت پایدار |
| نتیجه | Test Result / Session Analysis | درصد و شمار صحیح/غلط/بی‌پاسخ واقعی |
| مرور | Review Home / Review Questions | همان موتور جلسه، بدون player دوم |
| تحلیل | Analytics Dashboard | فقط aggregate واقعی با مخرج مشخص |
| تنظیمات | Settings | تم، پروفایل و وضعیت storage واقعی |
| حالت‌ها | Empty / Error / Loading | کامپوننت مشترک و اقدام متناسب |

صفحه‌های اهداف مستقل، تقویم، اعلان‌های هوشمند و streak فقط وقتی وارد محصول می‌شوند که قرارداد داده و تسک مستقل داشته باشند. برای شبیه‌شدن به تصویر، داده یا قابلیت ساختگی اضافه نمی‌شود.

## 5. معیار پذیرش بصری

- عرض 360 و 1280 پیکسل بدون overlap یا overflow کلی.
- هدف لمس حداقل 44×44 و focus قابل مشاهده.
- نوار موبایل در آزمون مخفی و کنترل‌های پاسخ در دسترس.
- حالت روشن، تاریک و کاغذی بدون hydration error.
- صفحه‌های خالی فقط یک پیام اصلی و یک CTA دارند.
- متن فارسی RTL، فرمول LTR و اعداد ذخیره‌شده استاندارد باقی می‌مانند.
